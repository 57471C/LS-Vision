# AGENTS.md

Guidance for AI coding agents working on LS-Vision.

## Project context

LS-Vision is a Tauri 2 + SvelteKit desktop app for bench-top kit verification using computer vision. Version 0.4.3. The high-level plan lives in `plan.md`. Prefer small, incremental changes that move the core loop forward.

## Architecture notes

- Frontend: SvelteKit routes under `src/routes/`. `src/routes/+page.svelte` is a thin shell: it creates the operator session from `src/lib/operator/session.ts`, provides the store from `src/lib/stores/operator.ts`, and renders `OperatorToolbar`, `CameraView`, and `ResultsPanel`. Settings stays on `src/routes/settings/+page.svelte`.
- Rust/Tauri backend: `src-tauri/`.
- Inference is ONNX Runtime in Rust (`detect_image`). The app does not start a Python process. A `.pt` file is a training checkpoint: the page warns and does not detect.
- YOLO letterbox lives in `src-tauri/src/vision/letterbox.rs`. The unpadded size is rounded, then the leftover pixels are split with `(pad - 0.1).round()`, the same top and left assignment Ultralytics uses. The canvas is RGB 114. The tensor is float32 NCHW in `[0, 1]` unless `tensorNormalization` in `vision/config.local.json` is `zeroTo255`, or the ONNX metadata key `normalization` / `tensor_normalization` says so. A saved config value wins. After inference, boxes and polygon points are unpadded, then the slot crop origin is added, so the coordinates are native sensor pixels. Millimetres use those sensor pixels, not letterboxed tensor pixels. The detect payload keeps `detections` and also returns `items` and `transform`. DINOv2 still letterboxes its 224 crop with ImageNet mean and does not use this gray pad.
- Stage 1 catalogue matching lives in `src-tauri/src/catalog/` and `src-tauri/src/inference/dino.rs`. Startup loads `vision/catalogue.json` into Tauri state and L2-normalises every stored embedding. A missing or empty file logs a warning and leaves an empty list. The file schema and `vision/catalogue-crops/` layout stay as they are. After YOLO, each box is cropped from the full-resolution frame. Normalised edges are converted to pixels and clamped to the frame. The crop is stretched to 224×224 with bilinear interpolation, ImageNet-normalised, and embedded with the DINOv2 session already loaded at startup. Cosine similarity is the dot product of the unit vectors. The overlay shows the top IC as `FAST-00124 (94%)`. A score below 0.50, or an empty catalogue, shows `No Match`. The payload also keeps the next three ICs. `match_box_dino` scores one box on the latest raw frame. The same 224×224 path embeds crops when Settings imports a catalogue, so a stored part matches itself. The BoM count still uses the YOLO class, the part rules, and the letterboxed vectors in `vision/dinov2-references.json`.
- Startup also tries to open a DINOv2 session from `models/dinov2_vits14.onnx` next to the exe, then the gitignored `src-tauri/models/dinov2_vits14.onnx` (224×224 input, 384-dim CLS output). A missing or unloadable file logs a warning and leaves the YOLO session unchanged. The loaded session is kept beside the YOLO session. `dinov2_status` reports whether it loaded and the input and output names and shapes. After detection, each box that survived the YOLO threshold and NMS is cropped, letterboxed to 224 without stretching, ImageNet-normalised, and run through that session. One stderr line per box gives the class, confidence, embedding norm, and the first four values. Test mode can save those embeddings under each box's IC. The map is kept in memory and written to `vision/dinov2-references.json`, next to `vision/config.local.json`. Startup loads that file. A missing or invalid file leaves the in-memory map unchanged. Settings > Parts > Update references opens a native file dialog that accepts .tar. The archive's catalogue.json names each part, and the JPEG crops live under crops/. A path `crops/<IC>/<file>.jpg` belongs to that IC. An IC is left out only when its crop list is empty or those files are not in the tar. Each crop is embedded with the DINOv2 session already loaded at startup. The IC, description, type, dimensions, crop paths, and embeddings are written to vision/catalogue.json, beside vision/config.local.json, and the JPEGs are copied under vision/catalogue-crops/. Startup loads that file. A missing or invalid file leaves the in-memory catalogue unchanged. Cancel says "No file selected." A bad archive, a missing DINOv2 session, or a write error leaves the saved catalogue in place and shows an error toast. Success says "Catalogue loaded N parts." View references lists each imported part, its description, type, dimensions, and crop thumbnails. Delete removes that one part. The dialog does not edit the other fields. This catalogue is separate from the detection reference file. A later detection adds the best cosine similarity against the references stored for that IC, and the same lines go to the operator console. `matchThreshold` in `vision/config.local.json` defaults to 0.70 and is clamped from 0.50 to 0.95. Settings > Training edits it. An IC with no saved threshold uses that score. When that IC has references, the box counts toward the BoM only when the score is above the threshold. With no reference for that IC, the box still counts. A missing session skips the embedding and does not change the count.
- Settings lists the execution providers this PC can run. CPU is always listed. DirectML is listed when DirectML and a Direct3D 12 adapter are present. CUDA is listed when an NVIDIA adapter and the CUDA execution provider libraries load. The current `ort` features are `ndarray`, `download-binaries`, `copy-dylibs`, and `openvino` only, so this binary does not contain DirectML or CUDA. DirectML is not listed, and a CUDA choice still opens the CPU session. The saved `inferenceEp` is used when the session is created. A provider that fails to start falls back to CPU. The saved choice is kept. Settings > Training > Use OpenVINO (Arc) is `useOpenVino` in that file, default off. Off keeps this ONNX Runtime path. On looks for `onnxruntime_providers_openvino_plugin.dll`, then `onnxruntime_providers_openvino.dll`, in `openvino/` next to the exe, then beside the exe, then `resources/openvino`. It registers that file with `Environment::register_ep_library` and loads the same `.onnx` files on that plugin's GPU device for both YOLO and DINOv2. The installer places those OpenVINO DLLs in the same directory as the exe. A present `openvino/` folder still wins, because the lookup checks that folder first. The linked ONNX Runtime build does not contain OpenVINO. If the DLL is missing, registration fails, or the GPU session does not start, the session stays on ONNX Runtime and the Training status line says so. The saved switch stays on.
- The operator preview is a paced canvas. It calls `capture_preview` (scaled to fit 1280×720) and waits for the next frame until the draw finishes. The interval follows Display FPS. `capture_snapshot` clones a separate still handle at the camera's full resolution, converts it to an RGB `RawFrame`, and stores that frame for barcode and detection. It does not stall the preview slot and it does not encode a JPEG. The camera callback hands the sample's media buffer to those handles and does not copy the pixels. The only JPEG is the one `capture_preview` encodes when the canvas asks for a frame.
- Settings > Camera > Preview can set a scale for the open camera. Set scale is shown only while admin is unlocked. The admin draws one straight line on the preview, then enters that length in millimetres. The page stores `scale` on that camera in `vision/config.local.json` (`mmPerPx`, plus the width and height of the image the line was drawn on) beside the other per-camera fields. The preview header shows the scale, for example `Scale 0.085 mm/px`. Measure, on that preview and on the operator camera pane, uses the same line. A finished line shows its pixel length and the real length. Each end is a 1px tick perpendicular to the line on screen, and the line stops at that point. With no scale stored for that camera, the line shows the pixels and "No scale set for this camera." Operators can measure. They cannot change the scale. A full-resolution snapshot uses the same factor, adjusted by image width, so the millimetres match the preview.
- The existing camera preview window (Settings > Camera > Preview) zooms with Ctrl+wheel and pans with Space+left drag. A Focus slider on that preview sets manual focus on the camera, from 0 to 100, and saves it for that camera. The same bar sets UVC exposure and gain. Auto on that bar returns the camera to autofocus and clears the saved manual value. A missing per-camera focus follows `uvcSettings`: manual `focusAbsolute` when `autoFocus` is false, and autofocus when `autoFocus` is true. Enter stores the full-resolution raw frame and saves the current preview JPEG. A modal suggests the last saved name, and adds ` (n)` when that file already exists in today's folder, so a save never overwrites. The last name is stored in `vision/config.local.json`. Images go to the Camera page training folder, default `Documents/ls-vision/training` (Documents even when LocalAppData exists), inside `dd-mm-yyyy`. The preview does not draw a class list, thumbnails, or the bench ROI. A Detect button, and the \ key while that window is focused, runs the active ONNX model on the latest raw frame at the saved confidence. The button label is Detect. Boxes and a short list stay on the current preview frame. With admin unlocked, click one or more boxes and Save as reference. Append adds those crop embeddings under the YOLO class. Replace keeps only the selected crops for that class. Other classes stay. The vectors are written to `vision/dinov2-references.json` and loaded again on startup. The Save button is hidden while admin is locked. An unlocked admin can also drag a temporary marquee on that still. The crop is embedded with DINOv2 only, then a small IC field (typed or picked from the model classes) and Tick or X save or discard that one vector. Append adds it. Replace keeps only that crop for the chosen IC. Other classes stay. The marquee is not written to the bench ROI. The drag is taken by a layer on the still, so a detection box does not swallow the press. While Set scale or Measure is on, that line takes the drag. A short press on a box still selects that box. An admin Crosshairs control on that preview, off by default, draws faint lines that follow the pointer and shows the point in pixels and millimetres from the camera scale. While a marquee is dragged, the same label shows the width and height. The lines sit on the preview image box, so they stay with the image when the window is resized. The marquee clears on X, Clear, Escape, a new Detect, or when admin locks. It does not run a BoM comparison. With no ONNX model loaded, the button is disabled.
- `InspectionCamera` in `src-tauri/src/camera/mod.rs` is the capture trait (`capture_frame`, `set_exposure`, `set_gain`, with default no-op `set_focus` and `set_white_balance`). The live preview and snapshot stay on the Media Foundation reader. `UvcBackend` writes `camera.uvcSettings` on that reader's open source after the mode is selected and before the first sample: manual exposure (`exposureAbsolute`, default 156), manual focus (`focusAbsolute`, default 25, the same 0–100 slider mapped onto the driver range), manual white balance (4500 K), and gain 0. A positive exposure against a negative log2 range is converted (156 becomes about -6) and the applied value is logged. A control the driver rejects is a warning and does not stop the stream. Later exposure, gain, and focus changes write the same open handle and do not pause frame delivery. `camera.type` selects the block. A missing type stays UVC. `pylonSettings` is loaded and unused. `camera.type` of `pylon` opens `PylonBackend`, logs that it is not linked, and capture returns "Pylon backend not linked yet" without starting the UVC stream. No Pylon SDK is linked. `camera.index` still chooses the open device. `deviceIndex` is kept equal to it. The loader does not replace `byIndex`, `scale`, or `detectRois`. `save_local_config` merges objects into the file on disk. A key the patch omits stays, including `scale`, another camera in `byIndex`, and `detectRois`. Arrays and other values replace. A null clears that key. A focus change on the active camera keeps the stored scale. `InspectionCamera` errors are `CameraError`.
- Start/Stop Feed ignores extra clicks for 1.52 seconds. While locked, the button reads Please wait, is disabled, and draws at half opacity.
- Part detection stores up to four regions in `detectRois` (normalised `x`, `y`, `w`, `h`, or null). `detectRoi` stays slot 1. Settings > Capture and the operator Set ROI controls edit one slot at a time. The blank slot choice edits nothing. With no slot set, `detect_image` reads the full frame and returns `{ detections, classes, items, transform }`. With any slot set, it crops each one, runs the same letterbox and ONNX path, and returns `[{ slot, detections, classes, items, transform }, ...]`. The live preview draws every saved slot. The snapshot draws every slot's detection boxes; two or more slots colour those boxes amber, cyan, lime, and magenta and tag them with the slot number. A single slot 1 still uses one result panel and stores slot 1. Clearing a slot packs the remaining regions to the front, and the result panels use that numbering at once. An empty list is full-frame detection. Each saved region stores `enabled`, default true. The operator page, while admin is locked, shows four squares beside Camera when a slot is saved: grey when that slot has no box, green when it is on, and red when it is off. A grey square is not a button, so the pointer stays an arrow. With no saved slot, the squares stay hidden. When every saved slot is off, the region outlines stay hidden. Keys 1–4 toggle a saved slot, and backtick turns every saved slot off. The flag is written immediately. Detection runs only on enabled slots. With every saved slot off, detection does not use the full frame. An operator cannot move or resize the boxes. Settings can flip the same flags. Barcode ROI stays a single region.
- Barcode decode crops the raw frame to `barcodeRoi` when one is saved. The page tries the native QR detector and ZXing on the preview JPEG, then `decode_barcode` reads that raw crop (QR and Code 39). A crop whose long edge is over 1920 pixels is halved until it fits, and that smaller image is read first, because a 4K symbol is missed. One trailing slash is removed. BoM lookup is JSON (`vision/sample-bom.json`), the job-card API, or MSSQL. Test mode looks up the typed code, shows the chosen file, and detects that file. A live decode still detects the latest raw camera frame.
- BoM lookup stays behind a simple interface so Settings can swap JSON, API, and MSSQL.
- Settings > Database stores `api.descriptionPath`. When the field is missing, the path is `/VisionAppApi/ListInventoryDescription`. A blank value turns the lookup off. After detection, the Not in BoM list shows the description stored on the matching catalogue part. A catalogue item code that has no description there, and is not on the loaded BoM, is posted as `{ "icList": [...] }` to the saved API base URL plus that path, with the existing `X-Api-Key`. Returned `Des` values fill that gap and are stored with the result. A blank path, a missing base URL or key, or a failed call leaves that code as the IC only. The BoM lookup itself is unchanged.
- The operator Console button and drawer show only while admin is unlocked (`sessionStorage` key `ls-vision-settings-open`). Lines are still recorded when the page is locked. Locking admin closes the drawer.
- Release builds enable the Tauri `devtools` feature, and the main window and camera preview set `devtools: true`. Ctrl+Shift+I is Tauri's shortcut. F12 calls the same inspector from `src/routes/+layout.svelte`.
- Pass and fail inspections are stored in SQLite under LocalAppData (`results/results.sqlite`), or Documents when LocalAppData is missing. When detection ran, the stored pass flag also requires every BoM line's seen count to meet or exceed the expected quantity, and no detected class outside that BoM. The row includes the job card number from the scanned label, or from the BoM when that lookup returns one. The detection snapshot is recompressed to JPEG quality 75 with the long edge at most 1280 and written under `results/images`. The database stores the relative path `images/{file}`. File names are `{jobCard}_{YYYYMMDD-HHMMSS}.jpg`. An empty job card uses the kit IC, then `result`. A name collision adds `-2`. Settings > Capture has "Do not save Pass / Fail results", on by default (`skipResultSave`). When it is on, or when Test mode is on, the row and the JPEG are not written. Settings > Database has an optional Results endpoint (`api.resultsPath`), blank by default. After a saved row, a non-blank path POSTs that result to `{api.baseUrl}{resultsPath}` with the `X-Api-Key` header. The body is the job card, the stored timestamp, pass or fail, the slot (1–4, default 1), the kit IC, the description, the saved detail, the relative image path, and the compressed JPEG as base64. The SQLite row stores that same slot. Older rows migrate to slot 1. Each post is a new insert. A failed post is logged and leaves the saved row in place. Operators open `/results` from the operator header and from the top of the settings rail. Delete shows only while admin is unlocked and removes the row and the JPEG.

## Conventions

- Keep operator-facing UI simple and clear (big pass/fail, minimal steps).
- Admin functionality (parts, cameras, BoM source, models) should be separable from the main operator flow.
- One kit type and one barcode per bench/job.
- Prefer explicit, readable code over clever abstractions at this stage.
- When adding vision features, keep the Rust ONNX path. Do not add a Python runtime process or a call to port 8008.
- The Windows installer targets Program Files (NSIS `perMachine`; the MSI already uses Program Files). Photos, snapshots, and logs go under LocalAppData, or Documents when LocalAppData is missing. Do not write them under Program Files. Training snapshots from the camera preview are the exception: they default to `Documents/ls-vision/training` even when LocalAppData exists, then a `dd-mm-yyyy` folder.
- ONNX models live in the Tauri app data `models` folder (`%APPDATA%\studio.lean.ls-vision\models` on Windows) for both `npm run tauri dev` and the installed app. The active filename stays in `vision/config.local.json`. Settings > Training > Update model copies an `.onnx` file there, makes that file the active model, and shows the destination path or the copy error. A file that fails the ONNX header check is rejected with "Selected file is not a valid ONNX model". The installer bundles `models/*` into `models/` next to the exe, and each OpenVINO DLL into the same directory as `ls-vision.exe`. DINOv2 loads from `models/`. The OpenVINO provider looks in `openvino/` first, then beside the exe. YOLO `.onnx` files are not bundled. A missing or failed model is reported on the operator page.
- Detection confidence is `confidence` in `vision/config.local.json`, from 0.15 to 0.80, default 0.45. Settings > Training saves it when it changes. `detect_image` uses it as the YOLO score threshold. Boxes at or below that score are dropped.
- Part rules live in `vision/config.local.json` as `partRules`. Settings > Parts edits them. Parent and child are chosen from the active ONNX model's `names` metadata (`model_class_names`). Each rule has a parent class, a child class, a condition (`contains` or `no-child`), and a result IC. A blank child is allowed only for `no-child`, and then any class inside the parent counts. After `detect_image` returns, and before the counts, the overlay, and the saved result, the operator page renames a parent box when the rule matches. `contains` matches when the child box center lies inside the parent, including the edge. `no-child` matches when it does not. Rules run from top to bottom against the model's class names, and the first match wins. Child boxes keep their model class. A child box whose center satisfied a matching contains rule is left out of the BoM count, the pass check, and the operator overlay. With admin unlocked, that child is a thin grey outline. The result IC keeps its normal box. An empty list leaves every class unchanged. A rule whose parent, or whose named child, is not in the class list returned with that detect is skipped. The other rules still run. Skipped rules are written to the operator console. When any rule was skipped, the operator page shows a dismissible notice: "Some part rules could not be applied (missing classes). Check Settings." Matches are written to the operator console.

## Current behaviour

1. Barcode read from the saved barcode ROI, on a paced live preview. The Rust read halves a region whose long edge is over 1920 pixels before it tries the full-size crop.
2. BoM lookup from JSON, the job-card API, or MSSQL.
3. Inspection result on the operator view. PASS requires a loaded BoM, every BoM line's detected count at or above the expected quantity, and no class outside that BoM. Each BoM line shows pass when the count equals the quantity, short when it is lower, and extra when it is higher. A box whose class has saved DINOv2 references is left out of that count when its best match is not above that IC's saved threshold, or `matchThreshold` when the IC has none. When more than one detect slot is set, the column shows one panel per slot that has detections, or per returned slot when a BoM is loaded. Slot 1 alone, or no slot, stays one panel. Clearing a slot packs the remaining regions and panels to the front. A saved slot that is off is left out of that detect. Turning every saved slot off does not fall back to the full frame. A missing barcode, a missing BoM, a short line, or an unexpected class is FAIL. A child class used by a matching part rule is not part of that count. Until detection finishes, the banner is incomplete. Kit found/expected stays an info line and does not set PASS. An unexpected class is a red X on the snapshot. A class on the BoM, including the warning label 2VDSWN02, stays a normal box. Extra boxes of a listed class are a quantity check, not a red X. The Not in BoM list groups the catalogue item code drawn on each box, not the YOLO class, and shows the description stored on that catalogue part. The description endpoint is used only when that text is missing.
4. Full-resolution RGB frame for a live barcode and the detection that follows it, without freezing the preview canvas. The only JPEG is the scaled preview. Test mode detects the chosen image file instead of that camera frame.
5. A finished pass or fail is saved when Capture allows it and Test mode is off. The detection snapshot is stored as a compressed JPEG. The row and the results POST include slot. One region, or a full frame, uses slot 1. Several slots save one row per shown panel. When a Results endpoint is set, that saved result is posted to the API. Test mode writes nothing and posts nothing.
6. Optional part rules rename a parent detection to a result IC before the BoM count and the overlay. A child used by that match is omitted from the BoM comparison. Operators do not see its box. Admin sees a thin outline. A rule that names a class the current model does not list is skipped, and the operator page shows a dismissible notice. With no rules, classes stay as the model named them.
7. Test mode can save DINOv2 embeddings for the detected boxes under each box's IC. They are stored in memory and in `vision/dinov2-references.json`, and loaded again on startup. A later detection logs the best cosine similarity against the references for that IC. When references exist for that IC, only a score above `matchThreshold` (default 0.70) counts toward the BoM quantity. The operator line then shows pass, short, or extra. With no saved reference for that IC, the box still counts and the embedding line stays as before. A missing DINOv2 session still skips the step. A missing or invalid reference file leaves the in-memory map unchanged. The camera preview, while admin is unlocked, saves only the selected boxes into that same file. Append adds the crop embeddings for those YOLO classes. Replace keeps only the selected crops for each selected class. The same window can drag a temporary marquee, embed that crop with DINOv2 only, and save the one vector under an IC the admin types or picks. That marquee does not change the bench ROI. A restart loads the file again. Settings > Parts > Update references opens a native .tar dialog, reads catalogue.json, embeds each JPEG under crops/ (including `crops/<IC>/<file>.jpg`) with the loaded DINOv2 session, and writes vision/catalogue.json plus the crop files under vision/catalogue-crops/. A restart loads that catalogue. Cancel says "No file selected." A bad archive or a missing DINOv2 session leaves the saved catalogue in place and shows an error toast. Success says "Catalogue loaded N parts." View references lists each part, with its description, type, dimensions, and crop thumbnails. Delete removes that part. The dialog does not edit the other fields. The parent and child part-rule editor stays on that page. An IC with no saved threshold still uses `matchThreshold`. The marquee drag is taken by a layer on the still, so a detection box does not swallow the press, and a short press on an embeddable box still selects it. Admin Crosshairs, off by default, follows the pointer and shows pixels and millimetres from the camera scale. While the marquee is dragged, the label also shows width and height.

8. Each detected box is labelled with the closest catalogue IC, for example `FAST-00124 (94%)`. An empty catalogue, a missing DINOv2 session, or a score below 0.50 shows `No Match`. The BoM table still counts the YOLO class. The Not in BoM list groups that catalogue IC and shows the description stored on the catalogue part. Part rules still rename that class and still hide a matched child. The catalogue label stays on the box.

9. Settings > Camera > Preview stores a scale per camera. The same preview sets UVC exposure, gain, and focus. Those controls are written on the open camera before the first frame and again once the stream is up. Measure and scale use the saved millimetres per pixel and do not read those controls. Set scale asks for one line and its length in millimetres, and writes that factor with the camera settings. The operator camera pane has Measure. Drawing a line shows pixels and, when a scale is stored, the length in millimetres. Each end is a 1px tick perpendicular to the line on screen. With no scale, it says "No scale set for this camera." A later camera save keeps a scale the patch does not mention. A restart reads the saved factor again. `camera.type` of `pylon` does not open the UVC stream.
